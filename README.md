# Keep on Keeping on · 工具封装

一个独立的 SillyTavern 前端扩展。它在本轮请求里把输入原文放进工具结果，也能要求模型用函数提交任务结果，最后只把提取的文本交回酒馆或原插件。两个功能可单独开启，也可用于通过酒馆接口发送的总结、填表和小剧场任务。不需要 MMDB-PG、酒馆助手、额外后端或新的 API 密钥。

## 安装与使用

1. 将安装包解压到酒馆的 `data/<用户目录>/extensions/`，让文件位于 `extensions/SillyTavern-Keep-on-Keeping-on/manifest.json`。默认用户目录通常是 `default-user`。也可直接把本项目文件夹复制到同一位置。
2. 刷新酒馆，在「扩展」面板中展开 **Keep on Keeping on · 工具封装**。
3. 按需勾选 **把本轮输入放进工具结果** 和 **用工具提交并提取任务结果**。首次安装时两项均关闭，升级会沿用已有开关。使用「严格」预设时，正常发一条消息，然后看面板的「最近请求」。例如显示 **已封装 3 条输入消息（strict_tools）**，表示本轮采用了酒馆保留工具的严格模式。原预设无需修改。
4. 输出默认允许模型自动选择。若需要每条回复都通过函数提交，可勾选 **强制模型调用结果工具**。面板会区分「已提取工具结果」和「模型直接返回结果」。
5. 要覆盖静默总结等后台任务，勾选 **也处理后台／未标类型请求**。此开关首次安装和升级时默认关闭，启用后沿用上面的输入、输出和强制调用设置。无需在本扩展重填模型或 API。

最近请求最多显示 8 条，按请求编号分别更新状态，包含生成类型、连接类型、模型和处理／跳过原因。记录只保留在当前页面，刷新清空；不记录提示词、结果、API 地址或鉴权字段。这里的 `normal` 也可能来自助手脚本，不能据此判定是否是主聊天。

## 一轮请求如何处理

例如用户发送「写一段雨夜的对话」，两项都开启时：

1. 扩展按当前提示词后处理找到最后一个用户回合。「严格」和「半严格」会把尾部连续的用户消息和中途插入的系统消息合成一个回合。例如时间线、玩家发言、格式要求会依次出现在同一个工具结果里。开头连续的系统提示保留在系统区。「合并」只合并相邻用户消息，未启用后处理时取最后一条用户消息。
2. 扩展在原处保留输入引用和媒体，本地生成 `kok_read_input` 调用，工具结果包含与调用一致的 `request_id` 和保存整段原文的 `input`。输出协议放在开头系统区的末尾，交付提醒放在输入引用中，模型最后读到工具结果。若有助手预填，读取记录接在预填之后；同时开启输出封装时，最后追加交付提醒。单次合成读取只需一次模型请求。
3. 模型调用 `kok_emit_answer` 时，扩展校验工具名、数量和参数，将唯一字符串 `content` 交给酒馆，保留换行、标签和 Markdown。自动模式也接受正常结束且只含普通正文的回复。工具调用与普通正文混杂、参数残缺或达到输出上限时会报错。

只开输入时，酒馆沿用原来的流式设置。开启自动输出时，OpenAI 兼容连接向上游取完整 JSON，按酒馆选择返回普通响应或流式事件。原生 Gemini 通过事件流取得结束原因。开启输出封装后，正文都是校验完一次显示。

## 连接与适用范围

- 适用于聊天补全的 **OpenAI、自定义 OpenAI 兼容、OpenRouter、Google AI Studio（Gemini）、Vertex AI（Gemini）** 连接。接口需要支持函数工具，强制模式还需要支持指定函数。自定义连接选用 MMDB 的 `pg-…-抗截断` 模型时由 MMDB 处理，保留它的原生续写能力。
- 处理普通聊天、重新生成、滑动生成单个候选、继续和代写。开启后台开关后，也处理 `quiet` 及省略类型、类型为 `null` 或空字符串的请求；未知的显式生成类型仍跳过。
- 文本补全、其他连接、已有工具声明或工具历史、结构化输出、多候选、搜索和生图请求按酒馆原样发送。后台开关不会解除这些兼容性限制。
- 继续生成时向前找到最近一个用户回合，按同样顺序封装。选用「单条消息」后处理时，输入封装会跳过，原因显示在面板。如果同时装有工具辞典，它已标记接管的请求由它处理。单独测试本扩展时请关闭工具辞典的输入和输出。
- 输出封装仅传递完整答复，不提升模型输出上限，不自动续写。原生 Gemini 在输出封装下用流式上游取得结束原因，再转换回酒馆当前需要的格式。

## 其他插件、脚本和独立模型

1.3.0 在公共请求层处理任务，不依赖具体插件名称。接管范围是酒馆主页面的 `fetch` 发往同源 `/api/backends/chat-completions/generate` 的 POST 请求，支持字符串／URL 配合 JSON 字符串 body，以及 `Request` 对象。请求使用哪个模型、独立 API、代理和鉴权配置，就继续使用哪一套；本扩展不切换酒馆主模型，不替调用方保存结果或修改表格。

| 调用方式 | 处理方式 |
|---|---|
| 总结、填表或小剧场使用 `quiet`，或者没有填写生成类型 | 开启后台开关后，在满足连接和工具兼容条件时封装 |
| 助手 `generate`／`generateRaw` 使用 `normal`，含自定义模型／API | 原本就由输入、输出开关控制，不依赖后台开关 |
| 返回 JSON 文本、`<tableEdit>` 指令、XML 标签等，再由原插件解析 | 将完整文本放入 `content`，提取后原样交回；不解析或执行其中的指令 |
| 原插件已经声明函数工具、工具历史、JSON Schema 或其他结构化输出格式 | 原样旁路，保留原插件协议，并显示跳过原因 |
| 直接请求外部 API，使用 XMLHttpRequest、自带网络库，或独立 iframe 的 fetch | 不在本版接管范围；iframe 若调用父页面助手 API，则取决于该 API 实际走的请求路径 |

输入封装仍按「最后一个用户回合」处理，不会把整段历史全部搬进工具结果。只有系统消息的任务可以单独使用输出封装。输出协议使用「原任务结果」表述，要求保留机器可读格式；实际模型是否遵守任务格式仍取决于模型能力。

开启输出封装后，原插件收到的是校验后的完整文本，逐字显示会变为整段交付。取消信号继续由原调用方控制；上游错误、截断和无效工具结果不会触发额外重试。多个插件同时改写请求时，仍需按实际安装组合联调。

## 验证与参考

无需安装依赖，Node.js 22 下运行 `npm test`。测试覆盖输入配对与隔离、多模态、各开关组合、JSON/SSE 正文提取、错误、截断及取消。1.3.0 增加后台开关、独立模型配置、填表文本保真、`Request` 及其覆盖选项、并发状态和兼容性旁路回归。可选验收服务：运行 `node tests/local-provider.mjs`，把测试酒馆的自定义连接地址设为 `http://127.0.0.1:18745/v1`，开启两项并发送「封装验收」。服务只监听本机，成功时回复两段固定中文。

1.1.0 使用 **SillyTavern 1.19.0（06bde939f）** 的实际后处理函数，对比了严格、半严格、合并和无后处理共 16 个组合。通过 MMDB-PG 的 OpenAI 转换函数和酒馆的 Gemini 转换函数核对了工具结果原文。输出测试采用模拟响应，未测量真实模型的文风或成功率。

1.3.0 的路径核对参考助手 **4.12.0（6897ed6c）** 的 [生成实现](https://github.com/N0VI028/JS-Slash-Runner/blob/6897ed6cda2ec27e8877e418161dfd3327010370/src/function/generate/responseGenerator.ts) 和本地“大总结”的副 API 实现。22 项自动化测试通过；另用真实浏览器加载模拟宿主，验证了后台开关保存、`Request` 请求、重复初始化、十个并发任务的八条记录、文本安全显示和 390 像素窄屏布局，浏览器无报错。上述验收使用模拟上游，不代表所有填表／总结插件或真实模型均已联调通过。

合成读取和正文工具参考 MMDB-PG 的 `src/server/input-read.mjs` 和 `src/server/anti-truncation.mjs`。1.1.0 的严格后处理适配、工具结果原文和自动交付方式参考《ホームの先の編舟者 · 工具辞典》3.2.1。扩展目录约定见 [SillyTavern 官方文档](https://docs.sillytavern.app/for-contributors/writing-extensions/#manifestjson)。
